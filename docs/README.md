## 一句話總結

把「司機 15 份 Google 表單的每日回報」自動轉成「政府制式申報 Excel」，並讓所有主檔只建一次、之後自動帶入 —— 把客戶每月 7 個人天的作業壓縮到一鍵匯出。

## 技術架構

| 層級 | 選擇 |
|---|---|
| 前端 | Vue 3 + TypeScript + Vite + Element Plus + Vue Router + Pinia + Axios，靜態 SPA 部署 Vercel |
| 後端 | Go 1.23 + Gin，部署 Cloud Run（另有 Cloud Run Job 負責匯出） |
| 資料庫 | Supabase（PostgreSQL 15）+ Supabase Storage + Supabase Auth |
| 排程／通知 | Cloud Scheduler ＋ Resend Email |

政府申報檔為 `.xlsx`，由 `excelize` 產生。詳見文件 02 §2。

## 尚未取得的規則

- **計薪規則** —— F7 司機薪資表不排入時程。
- **成本計算與核銷規則** —— P3 記帳功能不排入時程。
- **請假通知流程與接收設定** —— F10 司機請假通知業主功能待規則與名單確認後排入時程。

上述皆不影響 P0、P1 功能，資料表先行建立承接原始數據。

## 上線前阻斷條件

**僅剩一項**：政府平台是否接受 `.xlsx`（樣本為 `.xls`）需以系統產出的實檔實測驗證，未驗證前不得宣告 M1 完成。

> 原「規則 R7 未搭乘仍申報需書面確認」已於 2026-08-25 解除——該功能決議不實作，系統一律以司機回報為準，改以一般的搭乘紀錄更正功能承接填寫錯誤（[文件 01 §5 R7](01-需求規格與資料分析.md)、[文件 09 §4.7](09-開發規格書.md)）。

九項待確認事項已全數定案，決議見 [09-開發規格書 §12.2](09-開發規格書.md)；仍待客戶提供的資料見 §12.3，皆有暫行作法，不阻擋開發。

> 文件 09 為實作依據，與文件 01–08 衝突時以文件 09 為準（差異已列於 §12.1）。
